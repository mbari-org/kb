## Versioning and release

`src/version.js` is gitignored, generated by `vite-plugins/version-plugin.js` at Vite
`buildStart` and by `scripts/version/tag.js` (exact git tag if HEAD is tagged, else UTC
`YYYY.MM.DD-HHMM`, plus git metadata). Full docs: `docs/VERSION.md` (note: its
"Core Files" script names are stale — actual scripts live in `scripts/version/`).

Scripts (`scripts/version/`):

| Command | What it does |
|---|---|
| `yarn version:tag` | `tag.js` — regenerate `src/version.js` |
| `yarn version:check` | `check.js` — gates in order: clean working tree → `yarn lint` → full test suite → test-deploy |
| `yarn version:test-deploy` | `check.js` **and then** `test-deploy.js` (note: `check.js` already runs test-deploy, so this runs the whole gate twice) |
| `yarn version:release` | `release.js` — requires `main` + clean tree; same gates, then `tag.js`, bump `package.json` version, commit `v<version>`, create git tag. Does **not** push |

`test-deploy.js` requires the sibling repo `../vars-quickstart-public`: builds `dist/`,
`rsync -a --delete` into `../vars-quickstart-public/temp/nginx/html/kbeditor/`, restarts
nginx via `varsq docker restart nginx`, and smoke-tests `https://localhost/kbeditor/` for
the snippet `/kbeditor/assets/` (12 attempts × 5s; tunable via `VERSION_CHECK_*` env
vars).

Release sequence (from README, verified against the scripts):

1. On `main` with a clean tree, run `yarn version:check` and fix any failures.
2. Run `yarn version:release`.
3. `git push && git push --tags`.

## Git hooks

- Enable repo hooks: `bash scripts/setup-hooks.sh` → sets `core.hooksPath` to
  `.githooks`.
- `.githooks/pre-commit` (active): runs `node scripts/version/tag.js` before every commit
  (`src/version.js` is gitignored; this keeps the local version fresh).
- `.git-hooks/pre-commit` (legacy, not wired up): blocks non-ASCII/control characters in
  staged JS/TS/CSS/MD files.

## Docker deployment

- `build.sh`: runs `yarn build` locally, takes the latest git tag as `VCS_REF`, builds
  `mbari/kbeditor:<tag>` and `:latest`. On arm64 uses
  `docker buildx build --platform linux/amd64,linux/arm64 --push` (pushes both tags);
  on other platforms plain `docker build` + pushes only `:latest` (the version-tagged
  image is built but not pushed — asymmetry noted in `docs/project-status.md`).
- `Dockerfile`: copies the **prebuilt** `dist/` into the image as `./kbeditor` and serves
  it with `yarn dlx http-server . -p 5173 --spa` on `node:26-alpine` (no build inside the
  image). Serving from `.` with dist at `./kbeditor` matches the `/kbeditor/` base path.

## Debugging tips

- Version tooltip: hover the version in the navbar in dev for commit/branch/dirty info;
  click the refresh icon to regenerate without a server restart.
- `yarn profile` + Chrome tracing: the untracked `tmp/analyze-trace.mjs`,
  `tmp/attribute-long-tasks.mjs`, and `tmp/resolve-trace-names.mjs` scripts attribute long
  tasks to source lines via source maps.
- `Whoops` error boundary catches render/lifecycle errors app-wide; async errors are
  routed there explicitly (e.g. preference flush, taxonomy load) via `showBoundary`.
